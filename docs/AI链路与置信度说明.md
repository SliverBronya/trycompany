# 田诊助手 · 两个大模型怎么用、提示词怎么拼、置信度是什么

_面向答辩与二次开发的技术说明。所有结论都对着代码写，不凭印象。_

---

## 一、两个模型分别用在哪

系统接的是 **OpenAI 兼容协议**（`/chat/completions`），配了两个模型：

| 配置项 | 模型 | 能力 |
|---|---|---|
| `tz.ai.vision-model` | `glm-4.1v-thinking-flash` | 多模态，能读图 |
| `tz.ai.text-model` | `deepseek-flash`（DeepSeek V4.1-Flash） | 纯文本 |

**调用点一共 5 处，它们是严格分工的：**

| 业务动作 | 用哪个模型 | 代码位置 |
|---|---|---|
| 看照片写症状描述 | **视觉** | `ImageDescriptionService.tryLlm` |
| AI 诊断（有照片） | **视觉** | `DiagnosisService.tryLlm` → `chatWithImage` |
| AI 诊断（没照片） | **文本** | `DiagnosisService.tryLlm` → `chat` |
| 生成防治建议 | **文本** | `SuggestionService` |
| 农技问答 | **文本** | `QaService` |
| 生成巡田报告 | **不调模型** | `ReportService` 用已有结论拼装 |

几个关键实现细节：

- **图片是服务端读成字节、转 base64 data URL 内联发送的**，不是把 URL 给模型。
  因为上传的图存本地，外网模型根本访问不到 `http://127.0.0.1` 的地址。
  定位文件统一走 `UploadedImage.resolveToFile`（含越界校验，防止读上传目录之外的文件）。
- **没有对应 API Key 时不报错、不阻塞**：视觉链路检查 `isVisionAvailable()`，文本链路检查
  `isTextAvailable()`，缺 key 时自动
  退化为「预置样张映射 + 知识库检索」，功能完整可演示，界面会明确标出当前模式。
- **调用失败不抛异常**：`OpenAiCompatLlmClient` 把失败一律转成 `LlmResponse.fail`，
  由上层决定走哪条降级路径。5xx/超时按 `max-retries` 重试；429 单独按
  `rate-limit-retries` 退避重试（免费档被限流是常态，且它返回极快，值得等）。

## 二、提示词是怎么拼出来的

### 2.1 三层结构

```
系统提示词 = 共享硬约束（所有任务都有） + 本任务的输出格式与要求
用户提示词 = 本次业务数据 + 知识库参考（只有诊断/建议/问答有）
```

全部在 `PromptBuilder` 里，一个任务一对方法。

### 2.2 共享的 5 条硬约束

```
1. 只输出一个 JSON 对象，不要输出任何 JSON 之外的说明文字，不要用 markdown 代码块包裹
2. 【禁止编造用药信息】凡涉及农药名称、稀释倍数、施用浓度、每亩用量，
   只能复述「知识库参考」中已经明确写出的内容。知识库没写的，一律填 "未收录"
3. 结论要基于可见的症状特征与给出的知识库依据，不要臆测
4. 拿不准就降低 confidence，宁可说没把握，也不要给一个看起来很确定的错结论
5. 你的结论是辅助判断，不能替代农技人员现场诊断
```

这五条不是文案，是产品约束的落点：**第 2 条对应「不编造用量」，第 4 条对应「不硬给结论」。**
它们能否成立，靠的是提示词 + 后置校验两道，**不能只靠提示词**（见第四节）。

### 2.3 各任务追加的部分

| 任务 | 追加了什么 |
|---|---|
| 诊断 | JSON 字段定义：`diagnosisName / confidence / riskLevel / basis / alternatives` |
| 建议 | 四段式：`recognition / basis / prevention / medicine / safety / disclaimer` |
| 问答 | 第 6 条：知识库没覆盖时只给通用建议，**且不得出现任何具体用量数字** |
| 照片描述 | 一份逐项清单（部位→数量分布→形状大小边界→颜色对比与晕圈→立体形态→表面附着物→其他），外加 `observable` 字段 |

> **照片描述为什么要给「清单」而不是「要求详细」**：实测过。只写「只描述看得见的内容」，
> 同一张真实病叶照片拿回来的是「叶片上有多个浅色斑点，分布在不同位置」——
> 正确但等于没说，最有判断价值的「中央色深 + 周围黄色晕圈 + 密布」一个都没提。
> 换成逐项清单后立刻变成「叶面密布着病斑，布满整叶，病斑近圆形，约几毫米大小，
> 中央深褐色、边缘浅褐色且周围有黄色晕圈，表面稍粗糙」。
> **要模型给出信息，就给它一张逐项交代的清单；加限定词基本没用。**

### 2.4 知识库参考是怎么塞进去的（诊断任务）

```
【知识库参考】
--- 条目 1（相关度 29）---
名称：柑橘溃疡病
特征性表现（判这个病的关键依据）：病斑中央木栓化隆起并呈火山口状开裂；周围有明显黄色晕圈；…
完整症状：叶片、果实和枝梢均可受害…
鉴别要点（与易混病怎么区分）：最易与柑橘疮痂病混淆，区分看三处：① 病斑大小…
发生条件：…  防治措施：…  用药注意：…  安全说明：…
--- 条目 2 …
以上只是候选，不是答案。若候选多于一条，请逐条比对「鉴别要点」，
先排除不吻合的，再给出结论，并在 basis 里写清你排除了哪个、依据是什么。
```

这一段是 2026-09-14 那次改造的重点，两个变化：

1. **检索不自信时，不再把候选塞进去。** 原来无论检索可不可信都塞 top3，
   于是一张没有文字描述的照片会拿到「实蝇 / 木虱 / 缺锌」这种与画面毫无关系的条目
   作为「参考」，模型只能从里面挑一个 —— 这正是「什么病都像溃疡病」的机制。
   现在只有 `ragService.isConfident(hits)` 为真才注入，否则明确告诉模型「没有可靠参考」，
   并让它完全依据照片判断、按实际把握给分。
2. **新增「特征性表现」与「鉴别要点」两栏**，让模型有依据去做排除。

## 三、置信度是怎么生成的

**没有第二个模型来打分，也没有做概率校准。** 三个来源各自的产生方式完全不同：

| 结论来源 | 置信度从哪来 | 典型值 |
|---|---|---|
| `preset` 预置样张 | 人工登记在 `tz_image_preset.confidence` | 90 / 88 / 86 |
| `llm` 大模型 | **模型自己在 JSON 里输出的 `confidence` 字段**（0–100） | 60–90 |
| `fallback` 关键词降级 | **固定 55**，写死在 `DiagnosisService.FALLBACK_CONFIDENCE` | 55 |
| `manual` 人工 | 无 | — |

### 3.1 它意味着什么

- **模型那个数字是「自称的把握」**，不是统计意义上的正确概率。
  提示词要求它「拿不准就降低 confidence」，所以它更多反映的是
  「我看到的信息够不够支撑这个结论」，而不是「我历史上对这类图有多少准确率」。
- **降级路径固定 55 是刻意的**：它低于采信线 60，就是在坦白「这条结论没经过图像识别」。
  如果给它 80，界面上就分不出「AI 看图得出的」和「按文字检索凑出来的」了。

### 3.2 它怎么影响系统判断

只有一处硬作用，但很关键：

```
大模型路径：confidence < tz.ai.min-confidence（当前 60） → 不予采信，转降级
```

除此之外它**不参与**风险等级计算（风险来自模型输出的 `riskLevel` 或记录的严重度），
也**不参与**复查任务排期（排期只看风险等级：高 3 天 / 中 7 天 / 低 14 天）。

### 3.3 改造后新增的一条规则（很重要）

**模型看过照片、只是把握不足（比如 55）时，系统不再退回关键词检索。**

原因：退回去等于把图像证据整个丢掉、只按文字再猜一次，而纯文字检索恰好就是
「什么病都像溃疡病」的来源（溃疡病的症状文本里「病斑 / 隆起 / 晕圈」这类通用词最多）。
一边是模型看着图说不确定，一边是字面匹配给出一个自信的名字，采信后者就是把「猜的」
当成「看到的」。

现在的行为是明确告诉用户：

> 看过照片后，最可能是「柑橘疮痂病」，但把握只有 55，低于 60 的采信线，本次不作为结论。
> 建议补充症状描述，或换一张更清晰、离病斑更近的照片重试。

**用户宁可看到「最可能是 X，但把握 55」，也不想看到系统沉默、或者换一个纯文字猜出来的名字。**

### 3.4 怎么读界面上的置信度

- **≥ 60 且来源是「多模态大模型初诊」**：模型看图给的结论，可信度相对最高。
- **= 55 且来源是「知识库关键词检索降级」**：没经过图像识别，界面上有橙色降级提示。
  它的价值是「给你一个可追溯的检索结果」，不是「诊断结论」。
- **来源是「预置样张映射」**：演示保底路径，数值是人工登记的，与模型无关。
- 列表页的「来源」和「风险」两列要连起来看 —— 只看风险不看来源，
  会把降级结果误当成 AI 结论。

## 四、提示词管不住的地方（改造后靠什么兜）

提示词是「请求」，不是「保证」。实测中它至少会在两件事上失效：

| 想约束的事 | 提示词的实际效果 | 兜底手段 |
|---|---|---|
| 不许编造用药 | 基本有效，但会漏 | `DosageGuard` 后置校验：正则扫出所有用量表述，逐个比对知识库 `medicine_note`，收录的放行、没收录的一律拦截并替换为提示语（**双向都要成立**，否则「有出处」和「没出处」在界面上分不出来） |
| 只描述、不下结论 | 有效 | 描述这段文字只进「症状描述」字段，不写 `diagnosisName`；结论一律由诊断环节产生 |
| 别把照片描述写笼统 | 加限定词**无效**，给逐项清单才有效 | 清单式提示词 |
| 句首不要用指示语 | **无效**（两次都写成「这/这些柑橘叶片上……」） | 暂无。要根治得给句式示例（few-shot），代价是重新验证一轮 |

最后一行是有意留在这里的：**这类「格式类指令」模型经常照错不误，别继续加限定词，
直接换成示例。** 已在技能库里记下这条经验，避免下次又走一遍弯路。

## 二、首次运行

### 1. 环境自检

```powershell
powershell -NoProfile -File scripts\check-env.ps1
```

逐项探测 JDK17 / Maven / 离线仓库 / Node20 / MySQL / Redis / 端口 / 数据库内容，每项直接给结论，最后汇总。**退出码非 0 就是有失败项**，先解决失败项再往下走。

### 2. 构建后端

**先停后端**（它握着 `ruoyi-admin.jar`，不停掉打包会失败在 `spring-boot:repackage` 的 jar 改名那一步）：

```powershell
powershell -NoProfile -File scripts\stop-all.ps1
```

然后构建（离线，约 11 秒）：

```powershell
cd C:\Users\Mendel\Desktop\企业实训\田诊助手
set JAVA_HOME=C:\RuoYi\toolchain\jdk17
C:\RuoYi\apache-maven-3.9.9\bin\mvn.cmd -o -B -f backend\pom.xml -DskipTests ^
  -Dmaven.repo.local="C:\Users\Mendel\Desktop\企业实训\实训环境及系统资料\aicd\05-Maven\maven-repository" ^
  package
```

三个参数都不能省：
- `-o` 离线。`~/.m2/repository` 是空的，联网拉依赖会失败或极慢。
- `-f backend\pom.xml`——父 pom 在 `backend\` 下，不在项目根目录。少了它会报 `Could not find the selected project in the reactor`。
- `-Dmaven.repo.local=...` 指向课程离线仓库。

> 只构建单个模块（例如只跑 `ruoyi-system` 的测试）要加 `-am`，否则会因为兄弟模块 `ruoyi-common` 没装进本地仓库而报 "Cannot access ... in offline mode"。

### 3. 前端依赖

`frontend\node_modules` 已经随项目带来了（386 个包），**正常情况下不用装**。

万一被删了：npm 源是默认的 `registry.npmjs.org`，需要联网。本机有一份 1.1G 的 npm 缓存（`C:\Users\Mendel\AppData\Local\npm-cache`），可以先试 `npm install --prefer-offline` 看缓存够不够，不行就得联网。

## 三、日常启停

```powershell
# 起（幂等：已经起来的不会重复启动，随时可以再跑一遍当检查用）
powershell -NoProfile -File scripts\start-all.ps1

# 只起后端，跑接口自测用
powershell -NoProfile -File scripts\start-all.ps1 -NoFrontend

# 停（默认只停前端、后端和 ngrok 隧道，MySQL/Redis 留着）
powershell -NoProfile -File scripts\stop-all.ps1

# 连 MySQL/Redis 一起停
powershell -NoProfile -File scripts\stop-all.ps1 -IncludeInfra
```

四个进程都在后台跑，不弹窗，日志按组件写在 `logs\` 下：`backend.log`、`frontend.log`、`mysql.log`、`redis.log`（另有对应的 `.err.log`）。**出问题先看日志**。

`start-all` 启动后会轮询端口，确认真的监听上了才报「已就绪」，不会出现「脚本说起来了、实际没起来」。

## 五、演示数据

```powershell
python scripts\seed-demo.py            # 建/补齐演示数据（可重复执行）
python scripts\seed-demo.py --clean    # 清掉演示数据
```

脚本做三件事，**全部走真实接口，不直接写库**：

1. 用 Pillow 画三张标注了「示意图 · 非真实病叶照片」的演示图，上传，按**图片真实 MD5** 登记为预置样张
   （同时登记这段照片的**症状描述**，见下面「照片自动生成描述」）；
2. 建演示地块「柑橘示范园1号地」，为每张图建一条巡田记录；
3. 依次调 诊断 → 防治建议 → 巡田报告，复查任务由报告环节自动排出。

这样设计的原因：预置映射靠图片 MD5 命中，而 MD5 只有把图片真的上传之后才算得出来。用 SQL 手写哈希等于把「这张图」和「那条结论」的绑定关系凭空断言一遍，将来图片换了哈希就对不上。而且演示数据由真实链路跑出来，顺带就是一次全流程回归——`source`、`degraded`、`dosageGuardHit` 这些字段都是管道真的填的。

> **照片自动生成描述**：预置样张除了结论，还登记了一列 `symptom_text`（照片上看得见的症状），
> 存在 `tz_image_preset` 里。它让「上传照片 → 系统自动把症状描述填进表单」这件事
> **在不配 API Key 时也能用** —— 演示现场只要传这三张样图，描述框会被自动填好。
> 库里已有的三条样张若这一列是空的，跑一次 `sql\tz_photo_describe.sql` 回填即可（可重复执行）。

产出（截至 2026-09-12）：

| 记录 | 诊断 | 来源 | 风险 | 复查截止 |
|---|---|---|---|---|
| 柑橘溃疡病 | 置信度 90 | `preset` | 中风险 | 7 天后 |
| 柑橘红蜘蛛 | 置信度 88 | `preset` | 高风险 | 3 天后 |
| 柑橘缺镁 | 置信度 86 | `preset` | 低风险 | 14 天后 |

复查截止日期是按风险等级自动排的：高风险 3 天、中风险 7 天、低风险 14 天。

> 演示图是**标注过的示意图**，不是真实病叶照片。知识库 **15 条已全部填写真实公开发布的出处与用量**，
> 覆盖病害 / 虫害 / 营养问题三类；但用量是**特定区域特定年份的推荐值不是法定值**，
> 且不同来源给出的倍数可能不一致（条目里已如实标注差异）。正式使用前请替换为实拍照片，并由植保人员复核用量。

## 六、接入大模型（可选）

系统是**双路线**的：不配 key 也能跑完整闭环，只是诊断走「预置映射 + 知识库检索」，界面上会明确标出当前结果的来源。

要接真模型，设一个环境变量即可，**不要把 key 写进配置文件**：

```powershell
# 注意是 PowerShell 语法 $env:，不是 cmd 的 set
$env:TZ_AI_API_KEY = "sk-你的key"

cd C:\Users\Mendel\Desktop\企业实训\田诊助手
powershell -NoProfile -File scripts\stop-all.ps1
powershell -NoProfile -File scripts\start-all.ps1
```

两个要点：
- **必须和 `start-all.ps1` 在同一个 PowerShell 会话里设**。`Start-Process` 启动的子进程
  继承的是父进程的环境变量，换个窗口设了就传不进去。
- `set TZ_AI_API_KEY=...` 是 cmd 写法，在 PowerShell 里**不会报错但也不生效**——
  它会建出一个名字叫 `TZ_AI_API_KEY=sk-xxx` 的变量，然后你会以为接上了其实没有。
  想设成永久的用户级变量用 `setx TZ_AI_API_KEY "sk-你的key"`，但**要新开一个窗口才生效**。

设好之后先用自检脚本确认 key 和模型名是对的 —— 它**不经过后端**，直接按后端一模一样的
请求形态（base64 内联图片 + 只准输出 JSON）打服务商接口，所以不用等系统重启就能知道成不成：

```powershell
python scripts\check-ai.py
```

它会验三件事：key 能不能用、模型 id 存不存在、图片以 base64 内联发过去服务商收不收。
失败时把服务商的原始报错原样打出来，照它改配置即可。默认拿演示图做验证，
而演示图是印着「示意图」字样的程序生成图，**模型大概率回「无法判断」，这属于预期结果**，
脚本不检验识别准确率。

再用一句确认后端到底读到了没有：

```powershell
python scripts\test-api.py        # 第 2 组用例会打印本次诊断的来源
```

来源显示 `preset` 说明走的是预置映射（key 没读到，或图片命中了预置表——两者都正常）；
显示 `llm` 才是真的调通了大模型。

配置在 `backend\ruoyi-admin\src\main\resources\application.yml` 的 `tz.ai` 段。
**默认接的是智谱 GLM 的免费模型**：读图 `glm-4.6v-flash`、问答与报告 `glm-4.7-flash`，
一个 key 同时覆盖两条链路，在 https://open.bigmodel.cn 手机号注册即可拿到，不用充值。

**换服务商要改四项，不是一项** —— `provider` / `base-url` / `vision-model` / `text-model`。
模型名是各家独有的，只改 `base-url` 一定 404：

| 服务商 | `base-url` | `vision-model` | `text-model` |
|---|---|---|---|
| 智谱 GLM（默认，免费） | `https://open.bigmodel.cn/api/paas/v4` | `glm-4.6v-flash` | `glm-4.7-flash` |
| 阿里百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-vl-plus` | `qwen-plus` |
| 火山方舟（豆包） | `https://ark.cn-beijing.volces.com/api/v3` | 豆包视觉模型 | 豆包文本模型 |

三个坑：
- **视觉模型必须用 `glm-4.6v-flash`，不能用看着更像的 `glm-4v-flash`**。本项目把图片以
  base64 data URL 内联发送（见 `OpenAiCompatLlmClient.buildMessages`），而 `glm-4v-flash`
  只吃公网图片 URL，会直接返回 400；它的输出上限还只有 1K token，装不下四段式建议的 JSON。
- `glm-4.5-flash` 已下线，别再写回这个 id。
- `provider` 会写进 `tz_ai_call_log` 并显示在界面的来源标签上，改配置时一起改，
  别留着 `dashscope` 却调智谱 —— 那样日志会指向错误的服务商。

读图偏慢，所以 `timeout-seconds` 给到 90 秒、`max-retries` 只留 1 次——**超时或失败不会让用户干等，而是降级到知识库路径并把原因写进响应**。

## 七、常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 打包失败在 `spring-boot:repackage`，提示 jar 改名失败 | 后端进程还握着 jar | `scripts\stop-all.ps1` 再构建 |
| `UnsupportedClassVersionError: class file version 61.0` | 用了 PATH 上的 JDK 8 | 显式 `set JAVA_HOME=C:\RuoYi\toolchain\jdk17` |
| `Could not find the selected project in the reactor: ruoyi-system` | 父 pom 不在当前目录 | 加 `-f backend\pom.xml` |
| `Cannot access ... in offline mode and the artifact com.ruoyi:ruoyi-common ... has not been downloaded` | 只构建单个模块，兄弟模块没装进本地仓库 | 加 `-am` |
| `mysql: [ERROR] Unknown suffix '$' used for variable 'port'` | 在 PowerShell 里写了 `-P$MysqlPort` 这种连写，变量没展开 | 参数写成数组再 splat（见 `check-env.ps1`） |
| 执行 `.ps1` 报「字符串缺少终止符 / 缺少右 `}`」，行号指的地方看着没问题 | 脚本存成了无 BOM 的 UTF-8，PowerShell 5.1 按 GBK 读中文读散了 | 存成 **UTF-8 带 BOM** |
| SQL 报 `near '-vue.tz_knowledge_base'` 语法错 | 库名 `ry-vue` 含连字符，不加反引号会被当成减法 | 用 mysql 客户端的 `--database=ry-vue`，或给库名加反引号 |
| 登录页一直提示验证码错误 | 改了 `sys_config.sys.account.captchaEnabled` 但没清 Redis 缓存 | 删掉 Redis 里的 `sys_config:sys.account.captchaEnabled` |
| 界面显示「当前未接入大模型」 | 没设 `TZ_AI_API_KEY` | 正常降级行为，不是故障；要接模型见第六节 |
| 公网访问返回 `Blocked request. This host is not allowed` | vite 6 的 Host 头校验拦了 ngrok 域名 | 见第八节第 2 条，检查 `vite.config.js` 的 `allowedHosts` |
| 登录页提示密码错误，但口令明明没记错 | 改了口令，而页面里还预填着旧的 | 检查 `login.vue` 有没有把口令写回 `loginForm` |

## 八、口令与公网访问

### 1. 口令

| 账号 | 角色 | 口令 |
|---|---|---|
| `admin` | 超级管理员 | `wXsRUPApemfuyNt6` |
| `ry` | common（只有 `tz:*` 业务菜单） | `Nnc772vjaTqQx3TT` |

**为什么改**：原来两个号都是 `admin123`。只改 `admin` 是没用的 —— `ry` 的口令一模一样，
而 `common` 角色在田诊这 8 个模块上是完整的增删改查（含删除），并不是只读演示号。
另外 `frontend/src/views/login.vue` 原本把 `admin123` 预填在密码框里，
页面一挂公网就等于把口令印在登录页上；那处预填已经去掉。

改口令的两条路径不一样，踩过一次：

- 改**别人**的口令：系统管理 → 用户管理 → 重置密码（对应 `PUT /system/user/resetPwd`）
- 改**自己（admin）**的口令：个人中心 → 修改密码（`PUT /system/user/profile/updatePwd`）

对 `admin` 用「重置密码」会被拒，返回 `不允许操作超级管理员用户` —— 这是 RuoYi 的
`checkUserAllowed()` 有意挡的，不是权限没配好。

`scripts/test-api.py` 和 `scripts/seed-demo.py` 里内置的是上表口令。再改口令时不用动脚本：

```powershell
$env:TZ_PASSWORD="新口令"; python scripts\test-api.py
```

### 2. 挂公网（ngrok）

```powershell
powershell -NoProfile -File scripts\ngrok.ps1
```

隧道只指向前端 18081：`/dev-api` 由 vite 在服务端转给 18080，浏览器只认一个域名，
不用为后端再开第二条隧道。脚本跑完会把公网地址打出来（等价于手动 `ngrok http 18081`）。

免费版每次重启都换一个随机子域，所以别把地址写死在任何地方。

**两个必须知道的坑**（都踩过，而且症状都不指向真正的原因）：

1. **环境里有 `HTTP_PROXY` / `HTTPS_PROXY` 时 ngrok 会直接退出。**
   免费版不支持走 http/s 代理，报 `ERR_NGROK_9009`（"Running the agent with an http/s proxy
   is a Pay-as-you-go feature"）。现象是「ngrok 一闪而过、什么都不打印」，原因在
   `logs\ngrok-agent.log` 里。`scripts\ngrok.ps1` 已经显式清掉这几个变量再起进程；
   从 IDE / 沙箱 / 配了公司代理的终端里手动跑 `ngrok http 18081` 就会撞上。
2. **环境里有 `SERVER_PORT` 时后端不听 18080。**
   Spring Boot 的宽松绑定会把 `SERVER_PORT` 当成 `server.port`，优先级高于 `application.yml`，
   于是后端跑在别的端口、前端代理全线 502，而日志里只写「Port xxxxx was already in use」。
   从这类终端手动起后端时加 `--server.port=18080` 兜底。
   （`scripts\start-all.ps1` 在正常用户终端里不受影响。）

挂之前已经处理掉的三件事，别改回去：

1. **Druid 监控台已关**（`application-druid.yml` 里 `statViewServlet.enabled: false`）。
   它原本是 `enabled: true` + `permitAll()` + 默认口令 `ruoyi/123456`，
   stat 视图会把执行过的 SQL **连参数值一起**列出来。设 IP 白名单没用：ngrok 从本机转发，
   源地址看着就是 127.0.0.1。
2. **登录页不再预填口令**（同上）。
3. **vite `allowedHosts` 放开 ngrok 域名**。Vite 6 默认只应答 localhost/IP 的 Host 头，
   不放行的话公网访问会得到 `Blocked request. This host is not allowed`，
   而这时候隧道和后端其实都是通的，极易误判。

**故意保留、知悉即可的两处**：

- **Swagger 仍可匿名访问**（`/swagger-ui.html`、`/v3/api-docs/**`）。它只暴露接口清单，
  不含数据，且是演示时的一个展示点，所以留着。介意的话在 `SecurityConfig` 里把这两个路径
  从 `permitAll()` 挪走。
- **`/profile/**` 匿名可读**。上传的图片按 `年/月/日/文件名` 存放，文件名里带时间戳，
  拿到完整路径就能直接看图。演示数据是示意图，无所谓；换成真实果园照片就得留意。

> `token.secret` 还是 RuoYi 默认的 `abcdefghijklmnopqrstuvwxyz`。这个**不构成登录绕过**：
> RuoYi 的 token 只是个签名过的壳，里面装的是 Redis 里的登录态 UUID，光会签名而没有
> 一个活着的 UUID 依然过不了鉴权。属于该换但不紧急的一类，要换就改 `application.yml`
> 后重新打包、重启后端（所有人都要重新登录一次）。

### 3. 自助注册（对外开放）

登录页有「立即注册」，注册出来的账号默认拿 **`common` 角色**（田诊助手的业务菜单齐全，
不含任何后台管理权限）。

开关都在 `sys_config` 里：

| 参数键 | 当前值 | 作用 |
|---|---|---|
| `sys.account.registerUser` | `true` | 是否开放注册。后端 `/register` 直接看它，登录页的「立即注册」也看它 |
| `sys.account.registerRoleId` | `2` | 新账号自动授予的角色 id，逗号分隔可给多个；留空则不授角色 |

改完**必须清 Redis 缓存**（参数值是缓存在 Redis 里的，不清等于没改）：

```powershell
C:\RuoYi\redis\redis-cli.exe -p 16379 DEL "sys_config:sys.account.registerUser" "sys_config:sys.account.registerRoleId"
```

要收回注册能力（比如演示结束）：跑 `sql\tz_register.sql` 把 `registerUser` 改成 `false`。
前端「立即注册」会自动消失，后端 `/register` 也会直接拒绝。那个脚本可重复执行。

**接入时补的三处**（上游若依在这里本来是断的，别当成故障又「修」回去）：

1. **`/captchaImage` 现在会返回 `registerEnabled`。** 上游若依没有这个字段，而
   `/system/config/configKey/**` 是要鉴权的、匿名登录页读不到，所以借这个公开接口把开关带出去。
   注意它放在 `captchaEnabled` 为 false 的**早退之前** —— 放到之后的话，验证码一关
   （本项目开发期就是关的）登录页就永远拿不到开关。
2. **登录页 `register` 变量接上了。** 上游 `login.vue` 里 `const register = ref(false)` 之后
   再没赋过值，所以「立即注册」在原生代码里**永远不显示** —— 不是样式问题，是压根没接上。
3. **注册后补授角色。** 上游 `SysUserServiceImpl.registerUser()` 只 `insertUser`、不写
   `sys_user_role`，注册出来的账号能登录但**菜单和按钮全空**，等于白注册。
   现在由 `SysRegisterService.grantDefaultRole()` 按上面的参数补授。

> **公网开放注册的两个已知风险**，演示前自己掂量：登录验证码是关的
> （`sys.account.captchaEnabled=false`），而 `common` 角色在业务模块上有**删除**权限，
> 所以任何拿到网址的人都能注册并删改演示数据。演示完把 `sys.account.registerUser`
> 改回 `false`；数据被改乱了跑一次 `python scripts\seed-demo.py` 重灌。
> 想加一道门槛就把 `sys.account.captchaEnabled` 设为 `true` 并清 Redis —— 注意这个开关
> 登录和注册**共用**，开了之后登录页也会要求填验证码。

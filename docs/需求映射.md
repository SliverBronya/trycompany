## 二、巡田诊断核心链路

PRD「5. 核心流程」：**新建地块 → 巡田拍照 → AI 诊断 → 防治建议 → 巡田报告 → 复查任务**

| 环节 | 实现 | 关键文件 |
|---|---|---|
| 新建地块 | 若依标准 CRUD | `TzPlotController` / `TzPlotServiceImpl` |
| 巡田拍照 | 原生 `/common/upload`，落库时算图片 MD5 写入 `image_hash` | `TzScoutingRecordServiceImpl#fillImageHash`、`ai/ImageHash.java` |
| AI 诊断 | **三级链路**：预置映射 → 多模态大模型 → 知识库检索降级；都给不出就明确拒答 | `ai/DiagnosisService.java` |
| 防治建议 | 中文 bigram 检索知识库 + 四段式生成 + 剂量后校验 | `ai/RagService.java`、`ai/SuggestionService.java`、`ai/DosageGuard.java` |
| 巡田报告 | 汇总地块/症状/诊断/建议生成结构化报告，**同步自动排复查任务** | `ai/ReportService.java` |
| 复查任务 | 按风险等级自动定截止日（高 3 天 / 中 7 天 / 低 14 天） | `ai/ReportService.java`、`TzFollowUpTaskServiceImpl` |

**结论必须可溯源**：诊断结果带 `source` 字段（`preset` / `llm` / `fallback` / `manual`），
建议带 `source`（`llm` / `kb`），界面上以标签明示。这是「双路线」对用户的承诺——
用户任何时候都能知道这个结论是查表来的、还是模型给的、还是降级来的。

### 关于剂量拦截的一个设计取舍

被拦截的用量**不会出现在给农户看的正文里**，只以独立标签列在界面侧栏并写入调用日志。
原因：正文会被巡田报告整段引用，一个未经知识库核实的用量只要出现在正文中，哪怕前面写着
「已拦截」，农户照样能照着打下去——「已拦截」这个标签拦不住任何人，反而因为写在最后、
语气肯定，读起来更像在确认这个数字。拦截提示只说「拦了几处」，不复述数字本身。

### 比率指标不是用量（本轮修掉的一个缺陷）

`%` 也在受管单位里，于是建议正文里的**比率**会被误当用量。真实后果：正文模板拼进去的
「置信度 90%」被抹成「（用量待确认，请以农药标签为准）」，用户看到的是

```
柑橘溃疡病（置信度 （用量待确认，请以农药标签为准））
```

**拦错一个真用量是合规事故，把置信度改写掉同样是交付事故。** 修法是加一条语境排除：
数值紧邻的前字是「率」「效」或「置信度」时，该百分数（千分数）既不入白名单也不拦截，
原样留下。`发病率 80%`、`防效 65%` 因此不再被改写，而同一句里的 `2000倍液` 照拦不误。

边界**刻意不认「度」**——因为「浓度 0.5%」是货真价实的用量，必须继续受管。
`DosageGuardTest#doesNotTreatConcentrationAsRateContext` 就是钉这条边界的，
谁把 `RATE_CONTEXT` 顺手扩成「度」，这个用例会立刻失败。

### 检索阈值此前从未在真实语料上验证过（本轮发现）

知识库扩到 15 条后第一次用真实语料跑检索，发现两条**简写但准确**的症状描述被拒答：

| 描述 | top1 得分 | 分差 | 结果 | 卡在哪 |
|---|---|---|---|---|
| 叶面密布灰白色失绿小点，叶背有细小红色虫体 | 3.54 | 1.91 | 拒答 | 分差差 0.09 未达 `MIN_GAP=2.0` |
| 老叶叶脉间发黄，呈倒V形，叶脉仍绿 | 2.36 | 1.75 | 拒答 | 绝对分未达 `MIN_SCORE=3.0` |

**这不是扩库引入的回退。** 把同一批查询在扩库前的 5 条与现在的 15 条两份语料上
各跑一遍对照，**8 个用例的采信结论无一翻转**；打分是逐条独立计算的，
扩库只改变「第二名」是谁，两版 top1 得分逐条相同（7.39 / 3.54 / 14.65 / 2.36 / 3.50）。
泛词组反而更严格：top1 从 5.00 升到 5.75，分差从 0.45 **收窄到 0.29**。

真正的教训是 **`RagServiceTest` 的语料是 3 条手写 mock，阈值等于没测**。
因此补了 `RagServiceRealCorpusTest`，以真实语料快照（`src/test/resources/kb-corpus.json`）
为夹具，断言**采信结论**这个产品契约而不是具体得分（得分会随分词权重微调而变，
断言死数字只会让测试又脆又难维护）。

已知取舍已如实固化：简写描述被拒是**有意的保守代价**，拒答文案本身就在向用户
索取更具体的信息，补全后同一条描述即可命中。**没有为了让数字好看而调阈值**——
0.45（泛词）与 1.75（简写）之间的空档很宽，任何落在空档里的阈值都同样安全，
但改阈值属于产品行为变更，应当单独验证，不该顺手做。

## 六、权限与菜单

业务权限串全部以 `tz:` 开头，逐个都必须在 `sys_menu` 里有对应的菜单行，
否则 `v-hasPermi` 会把按钮直接从 DOM 里摘掉（不是禁用，是消失）。

- 菜单段位：`menu_id` 2000 起（库存量已用到 1060，`auto_increment=2000`），当前 **46 项**
- 结构：一级目录（PC 后台 / 移动端）→ 页面 `C` → 按钮 `F`
- 授权：`sys_role_menu` 给角色授权，超管默认拥有全部

`test-api.py` 第 15 组会**从后端 `.java` 源码里正则扫出所有 `@PreAuthorize` 权限串**，
再递归遍历菜单树，断言「没有任何一个业务权限串缺少对应菜单行」。改了权限没改菜单 SQL 时，
这条会直接失败。

### 知识库现状

已录入 **15 条**，落在 PRD 要求的 10–15 条区间内，覆盖三类问题。**每条的 `source`
都填了真实公开发布的出处**，不再是上一版的「示例数据，来源待补充」。

| 类别 | 条目 |
|---|---|
| 病害（6） | 柑橘溃疡病、柑橘炭疽病、柑橘疮痂病、柑橘树脂病（砂皮病/黑点病）、柑橘煤烟病、柑橘黄龙病 |
| 虫害（7） | 柑橘红蜘蛛、柑橘介壳虫、柑橘木虱、柑橘潜叶蛾、柑橘蚜虫、柑橘锈壁虱、柑橘实蝇（大实蝇/橘小实蝇） |
| 营养问题（2） | 柑橘缺镁、柑橘缺锌 |

出处类型：全国农技中心技术方案（含文号）、国家标准与行业标准（`NY/T 2920—2016`、
`GB/T 35333—2017`）、省市级农业农村部门发布、县级植保植检站《病虫情报》、公开出版书目。

**知识库 id 已显式钉在 100–114**（种子 SQL 的 INSERT 直接写 `knowledge_id`）。
此前依赖 `AUTO_INCREMENT`，结果每重载一次种子的 id 就整体前移一次，而
`tz_scouting_record.knowledge_id` 存的是**固定值**，于是记录挂到了不存在的条目上。
这个错在界面上完全看不出来 —— 建议是按**病名**再查一次知识库的，所以演示时
病名、来源标签、四段式建议全都正常显示，只有记录上的外键是悬空的。
现在 id 确定，记录与条目重新对得上；`seed-demo.py` 也改成**按病名解析 id**
并把写死的值降级为「期望值」比对，不一致就告警，不再让这种耦合悄悄失效。

#### 用量已录入，`DosageGuard` 现在是双向的

上一版 `medicine_note` 刻意不含任何用量，于是校验器只会「拦」不会「放」。
本版把出处里公布的用量原样录入，因此：

- 大模型说知识库**有**的用量 → 放行，界面标为可溯
- 大模型说知识库**没有**的用量 → 拦截并替换为「用量待确认，请以农药标签为准」

实测（3 条演示记录，兜底路径）：放行 4 / 14 / 7 处，拦截 0 处；
新增 4 个单测覆盖「比率指标不该被拦」这一新修的边界。

#### 这批用量的性质，答辩时别说过头

- 用量来自**特定年份、特定区域**发布的病虫情报与防治方案，是**推荐值不是法定值**；
  药剂的法定依据始终是所购产品标签。
- **不同来源给出的倍数可能不一致**（例如咪鲜胺在不同资料里从 600 倍到 1500 倍都有，
  缺镁的硫酸镁浓度从千分之一到百分之三都有）。本知识库按来源**如实收录、不擅自取中**，
  并在条目里把差异写明；`medicine_note` 只放行收录到的那些端点值。
- **炭疽病一条的出处相对弱**：该病的检索结果里没有官方植保站《病虫情报》，
  只能引到州级《农业灾害应急技术手册》与农技问答资料，已在该条 `remark` 中标注。
- 对外使用前应由植保专业人员复核。**代码不代劳这件事**——编造农技数据比留空更糟。

### 演示图片现状

3 张演示图是用程序画的**示意图**，图内直接印有「示意图 · 非真实病叶照片」字样。
它们的作用是让预置样张保底路径可复现，不是冒充真实病叶照片。
正式使用时必须替换为实拍照片（公开科普图或自拍），并同步更新 `tz_image_preset` 的哈希——
脚本按图片真实 MD5 登记，重跑 `seed-demo.py` 会自动重建绑定关系。

| 自训练病虫害识别模型（YOLO 等） | 标注数据集需要几千张图，两周做不完，且演示翻车风险高。课程评分点在「大模型 API + RAG + 业务闭环」 |
| 语音输入、GIS 地图 | PRD 明确首版不做 |
| 在线交易、支付 | PRD 明确供求只做线索撮合 |
| 向量数据库 / embedding 检索 | 知识库首版只有个位数条目，中文 bigram 检索 + 字段加权打分足够且**结果可解释**；引入向量库要额外的 embedding API 依赖和离线不可用风险。留作后续升级 |
| 微信小程序本体 | 需要 appid 与微信开发者工具，答辩现场不可控。用 H5 达到同等「降低农户使用门槛」的意图 |
